## 1. 产品定位与用户角色

### 1.1 产品定位

LYAdmin 是一套面向**企业内部运营/管理场景的通用后台管理基座**。它不直接承载业务，而是把鉴权、权限、日志、文件、仪表盘这些"每个后台都要重做一遍"的基础设施做成可复用的底座，让业务方只写页面。

PRD 定义的 5 个可衡量目标（G1~G5）当前达成情况：

| 编号 | 目标                                    | 达成    | 依据                                                                                                     |
| ---- | --------------------------------------- | ------- | -------------------------------------------------------------------------------------------------------- |
| G1   | 开箱即用（首次启动自动建表 + 种子）     | ✅      | `seed/index.ts` 串起 user/role/menu 三段种子，幂等；超管 admin/123456                                    |
| G2   | 权限可控（角色—菜单驱动，不改前端代码） | ✅      | 菜单树 → `permission.store.buildRoutes()` 动态注册；按钮用 `v-permission`                                |
| G3   | 操作可追溯（登录/写操作/HTTP 全记录）   | ⚠️ 部分 | 三类日志齐备，但**清空 HTTP 日志**与**代码生成落盘**两个高危写操作不在操作日志规则表内（见 3.2 REQ-014） |
| G4   | 交互一致（统一主布局 + 403/404/500）    | ⚠️ 部分 | 主布局统一；但**路由级无权限走 404 而非 403**，500 页无自动触发                                          |
| G5   | 工程规范（husky + commitlint）          | ✅      | 根目录统一 ESLint/Prettier/Stylelint + lint-staged                                                       |

### 1.2 目标用户与典型场景

| 用户                   | 典型场景                                                                  |
| ---------------------- | ------------------------------------------------------------------------- |
| 系统管理员（超管）     | 新系统上线：建角色 → 勾菜单 → 建账号 → 分配角色；审计谁在什么时候删了什么 |
| 业务运营（普通管理员） | 日常维护账号：改资料、重置同事密码、冻结离职账号；看登录异常              |
| 只读访客 / 审计方      | 只看不改：查用户名单、翻登录与操作日志做审计                              |
| 开发（本项目使用者）   | 用代码生成把新表的 CRUD 一次性铺出来，直接写进项目目录                    |

### 1.3 预置角色能力边界（真实授权，来自 `role.seed.ts`）

| 角色       | roleCode      | 授权方式              | 菜单 key 数 | 能力边界                                                                                                                |
| ---------- | ------------- | --------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------- |
| 超级管理员 | `super_admin` | `'ALL'`（全量菜单表） | 全部        | 不受任何权限裁剪（`requirePermission` 直接 next；前端 `hasPermission` 命中 `'*'` 通配）                                 |
| 普通管理员 | `admin`       | 显式 27 个 key        | 27          | 用户管理全按钮 + 三类日志（含导出/清空）+ 文件管理（上传/删除）+ 代码生成（预览/下载/落盘）；**不含角色管理、菜单管理** |
| 只读访客   | `viewer`      | 显式 9 个 key         | 9           | 首页 + 用户管理（仅查询）+ 三类日志（仅列表，无导出/清空）+ 个人中心；**不含角色/菜单/文件/代码生成**                   |

`admin` 授权明细（27）：`dashboard`、`system`、`system:user`、`system:user:{query,add,edit,remove,resetPwd,assignRole}`、`log`、`log:login`、`log:login:export`、`log:operation`、`log:operation:export`、`log:http`、`log:http:clear`、`file`、`file:{upload,remove}`、`tool`、`tool:gen`、`tool:gen:{preview,download,create}`、`profile`。

`viewer` 授权明细（9）：`dashboard`、`system`、`system:user`、`system:user:query`、`log`、`log:login`、`log:operation`、`log:http`、`profile`。

> **红线遵守情况**：`viewer` 未持有任何 `add / edit / remove / delete / clear / export / reset / assign` 类权限码。权限码层面**合规**，详见第 4.3 节。
