## 批次 A · 安全红线（建议最先做，合计约 1.9 人日）

### A1 · JWT 默认密钥当前正在被使用 🔴

| 项         | 内容                                                                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件       | `api/src/config/index.ts:51-52`、`api/.env`、`api/.env.example`                                                                                                                           |
| 现状       | `JWT_ACCESS_SECRET ?? 'ly_admin_access_secret'`，而 **`api/.env` 里用的就是这个默认值**，等于全网公开密钥，可伪造任意 Token                                                               |
| 改法       | ① 移除这两个默认值；② 新增启动自检：`NODE_ENV=production` 时缺任一密钥直接 `throw` 退出（fail-fast）；③ 生成两个 32 字节随机 hex 写入 `api/.env`；④ `.env.example` 标注「必填，禁止留空」 |
| 验证       | 生产模式缺密钥 → 进程启动失败并打印明确原因；正常启动 `npm run dev` 无影响                                                                                                                |
| **副作用** | ⚠️ **改密钥后所有已签发的 Token 立即失效，所有人需重新登录**。开发期影响可接受，生产环境建议安排在维护窗口                                                                                |

### A2 · `trust proxy` 过宽，IP 可被伪造

| 项   | 内容                                                                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件 | `api/src/app.ts:24`                                                                                                                                                          |
| 现状 | `app.set('trust proxy', true)` = **无差别信任所有 `X-Forwarded-For`**。攻击者发一个 XFF 头就能伪造来源 IP，直接影响 `getClientIp` 记录的真实性，也会让 A3 的频率限制形同虚设 |
| 改法 | 改为由环境变量控制跳数（`TRUST_PROXY`，默认不启用），只有在真正部署到反向代理后才配置                                                                                        |
| 验证 | 未配置时 `req.ip` 取真实 socket 地址；配置后才解析 XFF                                                                                                                       |

### A3 · 登录接口无频率限制

| 项                   | 内容                                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 文件                 | `api/src/routes/auth.routes.ts`（新增中间件）                                                                     |
| 改法                 | 零依赖滑动窗口：进程内 `Map<key, timestamp[]>`，key 用 `IP + username`，**5 次 / 5 分钟**超限锁 15 分钟，返回 429 |
| 验证                 | 连错 6 次第 6 次返 429；等窗口过期后恢复                                                                          |
| **局限（如实说明）** | 单机内存方案，进程重启即清空、多实例部署不共享。当前单体部署够用，将来集群化需换 Redis                            |

### A4 · 上传类型校验可被绕过（魔数校验）

| 项   | 内容                                                                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件 | `api/src/services/file.service.ts:85`（`saveFiles`）                                                                                                                      |
| 现状 | `file.mimetype` 由客户端提供，可伪造；`originalname` 同理                                                                                                                 |
| 改法 | 落盘后读前 16 字节做魔数比对（PNG `89 50 4E 47` / JPEG `FF D8 FF` / GIF `47 49 46 38` / WEBP `52 49 46 46`+`57 45 42 50` / PDF `25 50 44 46`），不匹配则删文件 + 返回 400 |
| 验证 | 用合法后缀 + 伪造 mimetype 的文本文件上传 → 被拒且**磁盘上没有残留文件**                                                                                                  |
| 依赖 | 必须在 A2 之后理解 IP 行为，但代码上互相独立                                                                                                                              |

### B5 · `/api/profile` 三接口：判定为「显式豁免」而非补码

**我的判断：不需要补权限码，应显式豁免并写进文档。**

理由是这三个接口操作的是**用户自己的**资料/密码/头像，任何登录用户修改自身账号是合理语义，不构成越权。为"看起来严格"而加码反而会让 viewer 连自己的密码都改不了。**处理方式**：在 `profile.routes.ts` 加注释固化这一结论，并同步到权限红线文档 §5.1，避免以后有人误补。
