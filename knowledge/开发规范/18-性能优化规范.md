# 18 - 性能优化规范

> 规范等级：🔴 硬性约定（Code Review 不通过） / 🟡 最佳实践（建议遵循）

---

## 一、构建阶段：包体积控制

### 1.1 路由懒加载（🔴）

每个路由页面必须使用动态导入，禁止在路由表中静态 import 页面组件。

```ts
// ✅ 正确（懒加载，独立 chunk）
{ path: '/order', name: 'Order', component: () => import('@/views/Order.vue') }

// ❌ 错误（首屏加载全部页面）
import Order from '@/views/Order.vue';
{ path: '/order', component: Order }
```

### 1.2 组件库按需导入（🔴）

- Element Plus：禁止 `app.use(ElementPlus)` 全量注册，必须由 `ElementPlusResolver` 按需自动导入（组件）+ `utils/element.ts` 子路径引入（命令 API）。
- 项目组件：`src/components` 由 `Components` 自动注册，勿在 `main.ts` 逐个 `app.component`（除 `appIcons` 这种按需注册的图标集外）。

### 1.3 构建期预压缩（已启用）

`vite-plugin-compression2` 已配置，同时产出 `.gz` / `.br`（原文件保留）。部署侧需开启预压缩读取（Nginx `gzip_static on; brotli_static on;`）才能真正受益。

### 1.4 vendor 拆分（🟡，已配置）

`build.rollupOptions.output.manualChunks` 已把 `echarts` / `vditor` / `element-plus` / `vue-vendor` / `vendor` 拆成独立 chunk，提升长缓存命中；`chunkSizeWarningLimit: 600`（KB）。单文件产物 > 600 KB 需在评审说明原因。

### 1.5 图片资源（🔴）

非 icon 类图片优先使用 WebP；大图（> 50 KB）走 CDN 或后端 `/static` 并配置缩放参数。

## 二、渲染性能

### 2.1 computed 缓存（🔴）

禁止在模板或 `watch` 中写复杂计算表达式，必须抽取为 `computed`。

### 2.2 v-memo（🟡）

列表 > 500 且更新频率低时使用 `v-memo` 跳过不变子树比对。

### 2.3 v-once（🟡）

纯静态内容使用 `v-once`，只渲染一次。

### 2.4 v-for 与 v-if 禁止同元素（🔴）

### 2.5 key 规范（🔴）

`v-for` 必须提供唯一 `key`，禁止使用 `index`。

### 2.6 事件监听自动清理（🔴）

使用 `useEventListener`（VueUse），禁止裸 `addEventListener` 不自解绑。

## 三、状态与计算性能

### 3.1 storeToRefs（🔴）

解构 Pinia state/getter 必须用 `storeToRefs`，方法可直接解构。

### 3.2 按领域拆分 store（🔴）

禁止一个巨型 store；跨组件复用逻辑放 `src/composables/`，store 只放全局/跨路由状态。

### 3.3 避免不必要响应式（🟡）

大对象/列表用 `shallowRef` / `shallowReactive` 减少深层代理开销（如渲染用的静态配置）。

## 四、网络与请求性能

### 4.1 防抖与节流（🔴）

搜索、resize、滚动必须加防抖/节流（优先 `useDebounceFn`）。

### 4.2 请求取消（🟡）

频繁切换的请求使用 `AbortController` 取消上一次；并发 401 由请求层单飞 + 队列重放解决（见 11）。

### 4.3 缓存策略（🟡）

字典等低频数据用 `useDict` 的模块级缓存 + 并发去重；菜单/权限有前端缓存（menuCache），非每次刷新全量拉取。

## 五、大数据量场景

### 5.1 虚拟列表（🟡）

长度 > 1000 必须使用虚拟滚动，禁止直接渲染全部 DOM。

### 5.2 大表单拆分（🟡）

超长表单按步骤/分区渲染，避免一次性挂载大量表单项。

## 六、响应式与弹层（本项目硬要求）

### 6.1 响应式优先（🔴）

窄屏（移动端）适配是默认要求。布局优先用 Tailwind 响应式（`flex-col lg:flex-row`），固定尺寸弹层必须响应式。

### 6.2 弹层响应式封装（🔴）

抽屉/弹窗/气泡等「固定宽度」弹层在窄屏（视口 ≤ 桌面固定宽度）会超出屏幕、出现横向滚动。必须走响应式封装：

- 通用弹窗用 `BasicDialog`（自带 ≤768px → 98%）。
- 自定义弹层用 `useResponsiveSize(desktopPx, mobile?)`（hooks：`src/composables/useResponsiveSize.ts`），返回响应式 `size`，不要写死 `size="860px"`。

```ts
// ✅ 正确
const { size } = useResponsiveSize(860);            // 抽屉：窄屏铺满
const { size } = useResponsiveSize(360, '92%');     // 气泡：窄屏留边距

// ❌ 错误
<el-drawer size="860px" />
```

## 七、监控与验收

- 产物增量 > 10% 需说明；本地可用 `npm run build` 观察 chunk 体积。
- 提交前自检含 `lint` / `stylelint` / `format:check` / `guard:deps` / 类型检查（见 README 贡献指南）。

## 常见错误

| 问题              | 原因                      | 解决                                     |
| ----------------- | ------------------------- | ---------------------------------------- |
| 路由切换很慢      | 页面打包过大              | 重型依赖动态 import / 拆 vendor          |
| 列表输入卡顿      | v-for 无 key / 模板中过滤 | 加 key、抽 computed                      |
| 切换 Tab 重复请求 | 未做请求去重              | fetching 锁 / 缓存                       |
| 弹窗打开卡顿      | 弹窗组件太重              | `defineAsyncComponent` 或按需加载        |
| 切换路由内存不降  | 事件未解绑                | `useEventListener` 自动清理              |
| 移动端弹层溢出    | 写死像素宽度              | 改用 `useResponsiveSize` / `BasicDialog` |
