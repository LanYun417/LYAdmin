# 19. ECharts 图表约定

图表的坑几乎都在**布局**上：数据对、颜色对，但图例压在曲线上、轴标签挤成一团、多序列填充糊成一块。
本文把踩过的那些写死成约定，新增图表照着抄即可。

## 19.1 统一入口与配色

- 从 `@/utils/echarts` 导入（按需注册了 Bar/Line/Pie + Grid/Tooltip/Legend/Graphic + Canvas 渲染器）；
  **禁止** `import * as echarts from 'echarts'`（会拖入全量 ~371 kB gzip）。
- 配色一律走 `@/utils/chartTheme`：`getChartPalette(isDark)` 拿 `text / textSecondary / axisLine /
splitLine / tooltip* / cardBg`，`verticalGradient(from, to)` 做面积渐变，`hexToRgba(hex, a)` 调透明度。
- **tooltip 必须显式用 palette 的三个颜色**（`backgroundColor` / `borderColor` / `textStyle.color`）：
  不设的话 ECharts 用内置亮色样式，暗黑模式下会刺眼。

## 19.2 布局约定（这几条是硬约束）

### 图例必须显式给 `top`

不指定位置时 ECharts 会把图例排到**绘图区底边内部**——实测（容器高 288px）图例落在 `y≈261`，
而绘图区是 `40~264`，于是图例压在曲线与面积上、还和 X 轴标签挤在一起：

```js
// ✅ 显式置顶，并给 grid.top 留出图例高度
legend: { top: 8, data: [...], textStyle: { color: palette.text } },
grid:   { top: 48, ... },
```

### `grid` 用固定小 padding + `GRID_AXIS_LABEL_FIT`

```js
grid: { left: 8, right: 16, top: 48, bottom: 8, ...GRID_AXIS_LABEL_FIT },
```

`GRID_AXIS_LABEL_FIT = { outerBoundsMode: 'same', outerBoundsContain: 'axisLabel' }` 会让 ECharts
**按轴标签的实测宽度自动让位**。所以 `left/bottom` 只给小值，**不要手写死**
（写死 `left: 44, bottom: 24` 的结果是：窄屏或数值变宽时标签被裁、底部挤在容器边缘）。
`grid.top` 是唯一需要手动留的——它要给图例腾地方。

### X 轴标签要控数量

采样类曲线动辄几十上百个点，交给 ECharts 自动抽点会得到「每 15s 一个、共 12 个」这种又密又难读的结果。
按点数反推间隔，目标**整屏约 6 个**：

```js
const labelInterval = Math.max(0, Math.ceil(points.length / 6) - 1);
xAxis: { axisLabel: { interval: labelInterval, margin: 12, fontSize: 12 } }
```

### 多序列不要都铺面积

两条半透明 `areaStyle` 叠加会把下方糊成一整块，既看不出信息又显脏。
**只给主序列铺**，并且用渐变让它向下淡出：

```js
areaStyle: {
  color: verticalGradient(hexToRgba(primary, 0.3), hexToRgba(primary, 0.02));
}
```

像「内存使用率」这种基本水平、只用来对照的序列，给一条 2px 线就够。

## 19.3 生命周期与主题联动

照 `views/home/components/TrendChart.vue` 抄：

```js
const resize = throttle(() => chart?.resize(), 100, { leading: true, trailing: true });
useResizeObserver(chartRef, resize); // 容器变化（侧边栏折叠/窗口缩放）都能适配
onMounted(() => {
  chart = echarts.init(chartRef.value);
  render();
});
onBeforeUnmount(() => {
  resize.cancel();
  chart?.dispose();
  chart = null;
});
watch(() => [appStore.dark, appStore.primaryColor], render); // 主题变化重绘
```

### ⚠️ 容器带 `v-if` 时必须懒初始化 + `flush: 'post'`

上面那套的前提是**容器在挂载时就存在**。一旦容器写成
`<div v-if="data?.ready" ref="chartRef">`（如"只有平台支持时才画网络图"），
挂载那一刻容器还不存在 → `onMounted` 里 `chartRef.value` 是 `undefined` → **图表实例永远不创建**，
面板一直空白。真实踩过：系统监控页的「网络吞吐」全白，而同一页没加 `v-if` 的「资源趋势」正常。

两处必须同时改，缺一处仍会空白（或间歇性空白）：

```js
// 1) 懒初始化：每次绘制前都尝试建实例，容器出现后再 init
const ensure = () => {
  if (!chart && chartRef.value) chart = echarts.init(chartRef.value);
  return chart;
};
const draw = () => {
  const instance = ensure();
  if (instance) applyOption(instance);
};

// 2) 触发绘制的 watch 必须是 post —— 默认 'pre' 在组件重渲染**之前**执行，
//    那时 v-if 的容器还没插入 DOM，ensure() 依然拿不到元素
watch(data, draw, { flush: 'post' });
// 或者：await fetch 之后先 await nextTick() 再 draw
```

排查特征：**同一页面里有的图能画、有的全白**，且白的那张容器带 `v-if` —— 基本就是这个原因。

## 19.4 不用起浏览器就能验证布局

ECharts 支持 SSR：可以在 Node 里把同一份 option 渲成 SVG，**量出图例/轴标签的实际坐标**，
用来确认"图例是否落在绘图区内""标签是否溢出容器"这类靠肉眼容易看漏的问题：

```js
const chart = echarts.init(null, null, { ssr: true, width: 900, height: 288, renderer: 'svg' });
chart.setOption(option);
const svg = chart.renderToSVGString(); // 解析 <text> 的 translate() 坐标即可核对
```

需要直接看图时，把 SVG 交给 `sharp` 转 PNG（后端依赖里已有 sharp）。
