# 17 - 性能优化规范

> 规范等级：🔴 硬性约定（Code Review 不通过） / 🟡 最佳实践（建议遵循）

---

## 一、构建阶段：包体积控制

### 1.1 路由懒加载（🔴）

每个路由页面必须使用动态导入，禁止在路由表中静态 import 页面组件。

```ts
// ✅ 正确（懒加载，独立 chunk）
{ path: '/order', name: 'Order', component: () => import('@/views/Order.vue') }

// ❌ 错误（首屏加载全部页面）
import Order from '@/views/Order.vue';
{ path: '/order', component: Order }
```

### 1.2 组件库按需导入（🔴）

- Element Plus：禁止 `app.use(ElementPlus)` 全量注册，必须由 `ElementPlusResolver` 按需自动导入（组件）+ `utils/element.ts` 子路径引入（命令 API）。
- 项目组件：`src/components` 由 `Components` 自动注册，勿在 `main.ts` 逐个 `app.component`。

### 1.3 构建期预压缩（已启用）

`vite-plugin-compression2` 已配置，同时产出 `.gz` / `.br`（原文件保留）。部署侧需开启预压缩读取（Nginx `gzip_static on; brotli_static on;`）才能真正受益。

### 1.4 vendor 拆分（🟡，已配置）

`build.rollupOptions.output.manualChunks` 已把 `echarts` / `vditor` / `element-plus` / `vue-vendor` / `vendor` 拆成独立 chunk，提升长缓存命中；`chunkSizeWarningLimit: 600`（KB）。单文件产物 > 600 KB 需在评审说明原因。

### 1.5 图片资源（🔴）

非 icon 类图片优先使用 WebP；大图（> 50 KB）走 CDN 或后端 `/static` 并配置缩放参数。

## 二、渲染性能

### 2.1 computed 缓存（🔴）

禁止在模板或 `watch` 中写复杂计算表达式，必须抽取为 `computed`。

### 2.2 v-memo（🟡）

列表 > 500 且更新频率低时使用 `v-memo` 跳过不变子树比对。

### 2.3 v-once（🟡）

纯静态内容使用 `v-once`，只渲染一次。

### 2.4 v-for 与 v-if 禁止同元素（🔴）

### 2.5 key 规范（🔴）

`v-for` 必须提供唯一 `key`，禁止使用 `index`。

### 2.6 事件监听自动清理（🔴）

使用 `useEventListener`（VueUse），禁止裸 `addEventListener` 不自解绑。

## 三、状态与计算性能

### 3.1 storeToRefs（🔴）

解构 Pinia state/getter 必须用 `storeToRefs`，方法可直接解构。

### 3.2 按领域拆分 store（🔴）

禁止一个巨型 store；跨组件复用逻辑放 `src/composables/`，store 只放全局/跨路由状态。

### 3.3 避免不必要响应式（🟡）

大对象/列表用 `shallowRef` / `shallowReactive` 减少深层代理开销（如渲染用的静态配置）。

## 四、网络与请求性能

### 4.1 防抖与节流（🔴）

搜索、resize、滚动必须加防抖/节流（优先 `useDebounceFn`）。

### 4.2 请求取消（🟡）

频繁切换的请求使用 `AbortController` 取消上一次；并发 401 由请求层单飞 + 队列重放解决（见 11）。

### 4.3 缓存策略（🟡）

字典等低频数据用 `useDict` 的模块级缓存 + 并发去重；菜单/权限有前端缓存（menuCache），非每次刷新全量拉取。

## 五、大数据量场景

### 5.1 虚拟列表（🟡）

长度 > 1000 必须使用虚拟滚动，禁止直接渲染全部 DOM。

### 5.2 大表单拆分（🟡）

超长表单按步骤/分区渲染，避免一次性挂载大量表单项。

## 六、响应式与弹层（本项目硬要求）

### 6.1 响应式优先（🔴）

窄屏（移动端）适配是默认要求。布局优先用 Tailwind 响应式（`flex-col lg:flex-row`），固定尺寸弹层必须响应式。

### 6.2 弹层响应式封装（🔴）

抽屉/弹窗/气泡等「固定宽度」弹层在窄屏（视口 ≤ 桌面固定宽度）会超出屏幕、出现横向滚动。必须走响应式封装：

- 通用弹窗用 `BasicDialog`（自带 ≤768px → 98%）。
- 自定义弹层用 `useResponsiveSize(desktopPx, mobile?)`（hooks：`src/composables/useResponsiveSize.ts`），返回响应式 `size`，不要写死 `size="860px"`。

```ts
// ✅ 正确
const { size } = useResponsiveSize(860);            // 抽屉：窄屏铺满
const { size } = useResponsiveSize(360, '92%');     // 气泡：窄屏留边距

// ❌ 错误
<el-drawer size="860px" />
```

### 6.3 顶栏（Navbar）移动端布局（🔴）

顶栏是 `justify-between` 的 flex 行，窄屏时左右两块会互相挤占——典型症状是**右上角头像被压成椭圆**。约定：

- 右侧控件组必须 `shrink-0`，不参与收缩；
- 头像等「固定尺寸」元素自身再加 `shrink-0` 兜底；
- 移动端（≤767px）隐藏昵称等文字，把宽度让给图标；
- 左侧开关 + 面包屑让位：容器 `min-w-0`，面包屑 `overflow-hidden whitespace-nowrap` 截断，不换行。

### 6.4 筛选栏与日期范围（🔴）

日期范围选择器（`el-date-picker` 的 `daterange` / `datetimerange`）是移动端筛选栏的主要溢出来源，**输入框与弹出面板两层**都要处理，现已全局解决、页面无需单独写：

| 层       | EP 默认                       | 全局处理（`src/styles/element.scss`）                                                                                       |
| -------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 输入框   | 固定 350px                    | ≤767px 时每个筛选项独占一行（`width:100%`、去掉 inline 表单右边距），选择器占满剩余宽度；覆盖所有 `SearchForm` 筛选项       |
| 弹出面板 | 固定 646px，body 最小宽 513px | ≤767px 时面板宽 = `calc(100vw - 16px)`、取消最小宽，两个月份上下堆叠、时间输入行改逐行，内容超高时面板内部滚动（70vh 封顶） |

> 新增筛选字段时直接用 `SearchForm` 的 `#filter` / `#filterAdvanced` 插槽，不要自造容器，否则上述全局样式不生效。
>
> 优先级提示：EP 按需样式在开发模式下加载更晚，覆盖 EP 组件样式时要带更具体的选择器前缀（如 `.el-picker-panel.el-date-range-picker`），否则同优先级会被 EP 覆盖（曾出现「样式写了但完全没变化」）。

### 6.5 列表「操作」列移动端收纳（🔴）

操作列按钮 **≥3 个**时，移动端（≤767px）只保留主操作，其余收进「更多」下拉；桌面端布局不变。列宽随端切换。

```vue
<el-table-column label="操作" :width="appStore.isMobile ? 120 : 300" fixed="right">
  <template #default="{ row }">
    <div class="table-action">
      <el-button type="primary" link @click="handleEdit(row)">编辑</el-button>
      <el-dropdown v-if="appStore.isMobile" trigger="click">
        <el-button type="primary" link>更多</el-button>
        <template #dropdown>
          <el-dropdown-menu>
            <el-dropdown-item @click="handleDelete(row)">删除</el-dropdown-item>
          </el-dropdown-menu>
        </template>
      </el-dropdown>
      <template v-else>
        <!-- 桌面端：原有全部按钮，布局与文案不变 -->
      </template>
    </div>
  </template>
</el-table-column>
```

要点：

- `.table-action` 已是 `flex + gap 8px`（`element.scss`）：**下拉触发器与按钮的间距/垂直对齐由容器 gap 统一负责**，不要再用 `el-button + el-button` 的 margin 思路——EP 的相邻按钮选择器对夹在中间的 `el-dropdown` 不生效，会出现贴边与不齐；
- 「更多」用与其他操作同款的纯文字链接按钮（`type="primary" link`），不加图标，保持原有观感；
- 下拉项沿用 `v-permission` 指令（无权限时元素整体移除，与按钮行为一致），并用 `text-[var(--el-color-*)]` 还原折叠前的彩色语义（删除项在 disabled 时不要叠加 danger 色）；
- 下拉里可用更完整的文案（「重置密码」而非「重置」）；
- 仅 1–2 个按钮的列不必收纳，避免为收纳而收纳；
- 已落地：用户管理（5 → 编辑 + 更多）、角色管理（4）、字典管理（3）。

## 七、监控与验收

- 产物增量 > 10% 需说明；本地可用 `npm run build` 观察 chunk 体积。
- 提交前自检含 `lint` / `stylelint` / `format:check` / `guard:deps` / 类型检查（见 README 贡献指南）。

## 常见错误

| 问题               | 原因                      | 解决                                     |
| ------------------ | ------------------------- | ---------------------------------------- |
| 路由切换很慢       | 页面打包过大              | 重型依赖动态 import / 拆 vendor          |
| 列表输入卡顿       | v-for 无 key / 模板中过滤 | 加 key、抽 computed                      |
| 切换 Tab 重复请求  | 未做请求去重              | fetching 锁 / 缓存                       |
| 弹窗打开卡顿       | 弹窗组件太重              | `defineAsyncComponent` 或按需加载        |
| 切换路由内存不降   | 事件未解绑                | `useEventListener` 自动清理              |
| 移动端弹层溢出     | 写死像素宽度              | 改用 `useResponsiveSize` / `BasicDialog` |
| 移动端头像被压扁   | flex 行内可收缩           | 右侧控件组与头像 `shrink-0`（§6.3）      |
| 移动端日期面板出屏 | EP 面板固定 646px         | 全局样式已处理；勿自造筛选容器（§6.4）   |
| 移动端操作列换行   | 操作按钮过多              | 收纳为「主操作 + 更多」（§6.5）          |
