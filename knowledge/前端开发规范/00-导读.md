## 与通用 Vue3 模板的关键差异（先读这段）

本仓库是 **单仓多工程（monorepo）**：根目录只放工程规范与 Git 钩子，`ly-admin-web/` 是前端工程（Vue 3.5 + Vite 8），`ly-admin-api/` 是后端工程（NestJS 12 + Prisma 7 + MySQL 8）。与通用 Vue3 模板相比，以下几处是必须遵守的**本地约定**：

1. 包管理器统一 **npm**（非 pnpm）；`.npmrc` 已配置 npmmirror 镜像；`package-lock.json` 必须提交入库。
2. Node 引擎声明 `>=24.0.0`（即 24+）；当前开发机为 Node 24.x，CI/部署需满足 `>=24.0.0`。
3. 已采用 **Vite 8（Rolldown）**、**Vue Router 5**、**Pinia 4**（含 `pinia-plugin-persistedstate`）、**Tailwind 4（preflight 关闭）**、**Element Plus 2.14**。
4. Element Plus **命令式 API（ElMessage / ElMessageBox）不自动导入**，统一从 `utils/element.ts` 桶文件引入；组件仍由 `ElementPlusResolver` 按需。
5. 自动导入的 d.ts 生成在 `ly-admin-web/` 根（`auto-imports.d.ts`、`components.d.ts`），并在 `eslint.config.mjs` 中显式忽略。
6. **零第三方运行时依赖**是硬约束，由 `scripts/deps-guard.mjs` 守护；新增运行时依赖须显式更新基线并说明。
7. 质量门禁除 ESLint / Prettier 外，还有 **Stylelint**（CSS/SCSS/Vue 样式）与类型检查（`vue-tsc` / `tsc`）。
8. 组合式函数目录名为 **`src/composables/`**（非 `hooks/`）。

## 硬性约定（违反即不通过 Code Review / 钩子）

- 包管理器统一 npm，禁止 pnpm/yarn 混用；`package-lock.json` 必须提交入库。
- Node 满足 engines `>=24.0.0`（即 24+）；依赖用 `^` 范围，不写死固定版本号。
- `<script setup lang="ts">` + 组合式 API，禁止 Options API。
- Vue / Vue Router / Pinia / VueUse 的 API 自动导入，禁止手动 import；Element Plus 命令式 API 必须从 `utils/element.ts` 引入，禁止 `from 'element-plus'` 整库引入。
- Prettier 三项铁律：semi: true、singleQuote: true、printWidth: 120。
- 样式优先级：Tailwind 工具类首选，SCSS 仅作兜底且必须 SFC scoped（见 19）。
- 新增第三方**运行时**依赖须通过 `npm run guard:deps -- --update` 更新基线并在评审说明；默认禁止。
- 提交信息必须符合 Conventional Commits，由 commit-msg 钩子（commitlint）强制校验。
- 响应式优先：固定尺寸弹层（抽屉/弹窗/气泡）必须走响应式封装（`useResponsiveSize` / `BasicDialog`），不得写死像素宽度。
