# 03 - 提交钩子与校验链

## 1. 校验链

```txt
git commit
  ├─ pre-commit  → npx lint-staged
  │     ├─ *.{js,mjs,cjs,ts,vue}              → eslint --fix → prettier --write
  │     ├─ *.{json,css,scss,md,html,yml,yaml} → prettier --write
  │     └─ *.{css,scss,vue}                   → stylelint --fix
  └─ commit-msg  → npx --no -- commitlint --edit "$1"
git push
  └─ pre-push    → npm run guard:deps
```

钩子由 husky 9 装配：根 `package.json` 的 `prepare: "husky"` 在 `npm install` 时接管 `.git/hooks`，把 `.husky/` 下的脚本挂到对应生命周期。

## 2. 配置文件

| 文件                     | 作用                                         |
| ------------------------ | -------------------------------------------- |
| `.husky/pre-commit`      | 调用 lint-staged，对暂存文件执行 lint/format |
| `.husky/commit-msg`      | 调用 commitlint 校验提交信息                 |
| `.husky/pre-push`        | 调用 `guard:deps` 校验依赖基线               |
| `commitlint.config.cjs`  | 提交信息规则（type 白名单、首行长度）        |
| `.czrc`                  | cz-git 交互式提交的 type / scope 词表        |
| `lint-staged.config.cjs` | 暂存文件按类型分派命令、过滤生成物           |

> lint-staged 的文件过滤与 Windows 命令行长度适配见 [`前端开发规范/14-Husky与lint-staged`](../前端开发规范/14-Husky与lint-staged.md)；依赖基线规则见 [`前端开发规范/15-依赖守护与版本策略`](../前端开发规范/15-依赖守护与版本策略.md)。

## 3. 团队约定

- **禁止绕过**：不得使用 `git commit --no-verify` / `git push --no-verify`。钩子失败先修问题；确属误报，改配置并在 PR 说明，不留后门。
- lint-staged 修复后会自动重新 `git add`，提交进去的就是修复后的内容。
- 钩子命令统一走 `npx` / `npm`，保证 Windows 与 macOS 行为一致。
- `package-lock.json` 必须提交入库；`dist/`、`node_modules/`、`ly-admin-api/uploads/`、`logs/`、`cache/`、`web/` 等产物不入库。

## 4. 本地等价命令（CI 可直接复用）

```bash
npm run format:check     # Prettier
npm run lint             # ESLint（--max-warnings 0）
npm run stylelint        # Stylelint
npm run guard:deps       # 依赖基线
```

后端与前端另有各自的类型检查 / 测试，见两端规范的门禁章节。CI 不装配 husky（未执行 `npm install` 到根时钩子也不存在），必须把上述命令显式写进流水线。

## 5. 常见错误

| 现象                                                 | 原因                                  | 解决                                                       |
| ---------------------------------------------------- | ------------------------------------- | ---------------------------------------------------------- |
| 提交时钩子不执行                                     | 只在子工程装依赖，根钩子未装配        | 在**根目录** `npm install`（触发 `prepare` → `husky`）     |
| `type may not be empty` / `subject may not be empty` | 提交信息不符合 Conventional Commits   | 用 `npm run commit` 生成，或按 `type(scope): subject` 手写 |
| `header must not be longer than 100 characters`      | 首行过长                              | 精简 subject，把细节移入 body                              |
| `type must be one of [...]`                          | type 不在白名单                       | 从 [01-提交信息规范](./01-提交信息规范.md) 的表中取值      |
| Windows 上 `commit-msg` 报路径错误                   | 脚本用了 bash 特有语法                | 保持脚本为简单命令，参数用 `"$1"`                          |
| lint-staged 卡住或报「参数太长」                     | 误 add 了产物，或一次性带入数百个文件 | 检查 `.gitignore`；配置已按批切分，见前端 14               |
| 钩子里 `npx` 找不到                                  | GUI 客户端环境变量缺失                | 用终端提交，或在 GUI 中配置 PATH                           |
| push 被 `pre-push` 拦截                              | 运行时依赖偏离基线                    | 见前端 15；确需变更走 `npm run guard:deps -- --update`     |
