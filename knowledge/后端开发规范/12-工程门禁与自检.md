# 12 - 工程门禁与自检

## 1. 提交前必跑

在 `ly-admin-api/`：

```bash
npm run typecheck        # tsc --noEmit --incremental false
npm run lint             # oxlint --type-aware src/ test/
npm run test             # vitest 单测
npm run test:e2e         # 契约 + 冒烟（需 MySQL / Redis）
npm run build            # nest build
npx prisma validate      # schema 合法性
npm run prisma:comments:check   # 库内 COMMENT 是否漂移
```

在仓库根目录：

```bash
npm run guard:deps       # 三处 package.json 运行时依赖是否偏离基线
npm run guard:imports    # 已入库文件的相对导入是否可解析（等价于干净克隆能否构建）
npm run format:check     # Prettier
```

全绿才提交；提交信息见 [`Git 提交规范/01`](../Git提交规范/01-提交信息规范.md)。

## 2. 各门禁在防什么

| 命令                    | 防的问题                                                                        |
| ----------------------- | ------------------------------------------------------------------------------- |
| `typecheck`             | 类型错误；`--incremental false` 避免 `dist/tsconfig.tsbuildinfo` 缓存掩盖新错误 |
| `lint`                  | 未使用变量、`String(unknown)`、重复联合类型等；目标 **0 error / 0 warning**     |
| `test`                  | 纯函数回归（分页、树、时间、CSV、口令）                                         |
| `test:e2e`              | 响应信封 / 分页键 / 状态码 / 种子常量 / CSV 字节等对外契约                      |
| `build`                 | 装饰器元数据、ESM 解析、`rootDir` 边界                                          |
| `prisma validate`       | 目录式 schema 的语法与合并合法性                                                |
| `prisma:comments:check` | schema 的 `///` 与库内 COMMENT 是否一致                                         |
| `guard:imports`         | `.gitignore` 误伤源码目录导致「本地能跑、干净克隆缺文件」                       |
| `guard:deps`            | 运行时依赖漂移                                                                  |
| `format:check`          | 格式漂移                                                                        |

## 3. 测试分层

| 层   | 文件                        | 依赖             | 内容                                      |
| ---- | --------------------------- | ---------------- | ----------------------------------------- |
| 单测 | `test/utils.spec.ts`        | 无               | 分页、树、CSV、时区、口令哈希             |
| 冒烟 | `test/app.e2e-spec.ts`      | App + DB         | 健康检查、装配一致性                      |
| 契约 | `test/contract.e2e-spec.ts` | App + DB + Redis | 信封、分页、种子常量、校验文案、CSV、日志 |

- e2e 用 `createTestApp()`（`test/setup-app.ts`）装配，与 `main.ts` 共用 `configureApp` **和** `OkExpressAdapter`。
  不要在 spec 里手写 `createNestApplication()`，否则会缺校验管道与恒 200 行为。
- `vitest.config.e2e.ts` 设置了 `fileParallelism: false`：多个 spec 会各自启动应用并写种子，串行避免互相干扰。
- 契约断言口径：
  - **精确**：响应信封、分页键集合、状态码、种子身份常量、被刻意收窄的响应形状、CSV 表头 / BOM。
  - **包含 / 下界**：会随使用增长的数据（菜单数、日志条数）与运维可改的参数值。
- 新增对外接口时补一条契约用例；改动响应结构必须同步更新 golden 断言。

## 4. Prettier / ESLint

- 格式化以根 `.prettierrc.json` 为准：`semi: true`、`singleQuote: true`、`printWidth: 120`。
- ESLint flat config 覆盖 `ly-admin-api`；`src/generated/**`、`dist/**` 已忽略。
- 生成物（`src/generated/prisma`）不要格式化、不要手改。

## 5. Prisma 相关检查

```bash
npx prisma validate                 # schema 语法
npm run prisma:comments:check       # COMMENT 漂移
npx prisma db push                  # 同步表结构（会提示是否有变更）
```

- `db push` 输出 `The database is already in sync` 表示结构一致。
- `db push --force-reset` 会清空数据与 COMMENT，只在本地重建时使用，之后补跑 `prisma:comments`。

## 6. 常见「假绿」

| 现象                           | 原因                                     | 处理                                                 |
| ------------------------------ | ---------------------------------------- | ---------------------------------------------------- |
| 本地全绿，新克隆构建失败       | 源码目录被 `.gitignore` 误伤，文件未入库 | 跑 `npm run guard:imports`，检查 `.gitignore`        |
| typecheck 通过但启动报类型错误 | `dist/tsconfig.tsbuildinfo` 缓存         | 用 `npm run typecheck`（已带 `--incremental false`） |
| lint 通过但有 warning          | 只看退出码                               | 门禁要求 0 warning；`oxlint` 输出需逐条清零          |
| e2e 通过但接口在浏览器 500     | 测试与生产装配分叉                       | 确认新配置写进了 `configureApp`                      |
| 种子改了但库里没变             | 种子只增不删；启动时才执行               | 重启服务或 `npm run seed`                            |
