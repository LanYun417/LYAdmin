# 11 - 代码生成器

## 1. 它做什么

读取真实表结构 → 预览生成物 → 下载 ZIP 或直接写入项目目录，产出**可直接运行**的前后端 CRUD 骨架：

```
backend/
├─ modules/<module>/<business>/
│  ├─ <business>.module.ts
│  ├─ <business>.controller.ts
│  ├─ <business>.service.ts
│  └─ dto/<business>.dto.ts
└─ prisma/<table>.model.prisma
frontend/
├─ api/<business>.ts
└─ views/demo/<business>/index.vue
README.md
```

生成物风格对齐仓库现有代码（`modules/dict`、`src/api`、`views/system/dict`），
遵循 ESM `.js` 后缀、`ResponseEnvelope`、`parsePagination` / `buildPageResult`、`AppException`、
`@RequirePermissions`、`@OperationLog`、`MSG` 等约定。

## 2. 接口与权限

| 端点                             | 权限码              | 说明                 |
| -------------------------------- | ------------------- | -------------------- |
| `GET /api/gen/tables`            | `tool:gen:list`     | 库表列表             |
| `GET /api/gen/tables/:tableName` | `tool:gen:list`     | 表结构 + 字段注释    |
| `POST /api/gen/preview`          | `tool:gen:preview`  | 预览生成物（不落盘） |
| `POST /api/gen/download`         | `tool:gen:download` | 下载 ZIP             |
| `POST /api/gen/create`           | `tool:gen:create`   | 写入项目目录         |

四个写权限刻意分开：只读角色不应获得 preview / download / create，避免越权导出源码或写盘。

## 3. 安全约束

- **表名白名单**：`tableName` 必须与 `information_schema` 中真实存在的表一致，不接受任意 SQL 片段。
- **命名白名单**：`moduleName` / `businessName` 只允许字母开头、字母数字组合（`NAME_PATTERN`）；
  业务名会拼进路径，必须挡住 `../` 之类的路径穿越。
- **写入范围**：落盘前 `resolve` 后校验目标必须在 `ly-admin-api/src` 或 `ly-admin-web/src` 内（双重防御）。
- **覆盖策略**：同名文件默认拒绝（409），`overwrite: true` 才覆盖。

## 4. 自动接线与锚点

| 目标                             | 方式                                          |
| -------------------------------- | --------------------------------------------- |
| `src/app.module.ts`              | 插入 import 行 + `imports` 数组项（语法匹配） |
| `prisma/schema/generated.prisma` | 在 `// [GEN-ANCHOR]` 之前插入 model 片段      |
| `src/prisma/seed.service.ts`     | 在 `// [GEN-ANCHOR]` 之前插入菜单 / 按钮种子  |

- 锚点匹配规则：行首（trim 后）以 `// [GEN-ANCHOR]` 开头，说明文字里提到该标记不会误命中。
- 锚点缺失时**不做半截修改**，返回 `no-anchor` 并写进 `manualSteps`，由人工接线。
- 幂等：目标已包含待插入内容（import 路径 / 模型名 / 业务名）时跳过。

> 不要删除 `generated.prisma` 与 `seed.service.ts` 里的锚点注释；它们是生成器的唯一插入点。

## 5. 生成后仍需人工完成

1. `npm run prisma:push` + `npm run prisma:comments` + `npm run prisma:generate`。
2. 检查生成 DTO 的字段校验是否符合业务（生成器只按列类型给基础规则）。
3. 补权限码到菜单种子（生成器已插入按钮节点，但角色授权需在界面上勾选）。
4. 补测试：至少一条列表接口的契约断言。
5. 检查生成页面的字段控件（字典下拉 / 树形父级）是否需要在 `columnOptions` 中重新指定。
