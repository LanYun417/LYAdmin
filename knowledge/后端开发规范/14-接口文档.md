# 14 - 接口文档

## 1. 是什么

后端提供一个**公开接口** `GET /api/docs`，返回全部接口的清单 JSON（按业务模块分组）；
前端「接口文档」菜单页拉取该 JSON 并用 Element Plus 自绘渲染成可检索的文档页。

- 后端接口：`src/modules/docs/docs.controller.ts`（`@Public()`，`@Controller('docs')`）。
- 前端页面：`ly-admin-web/src/views/docs/index.vue`（菜单 key `docs`、路由 `/docs`）。
- 适用场景：接口自查、联调、交接；不依赖任何第三方 UI（如 Swagger UI），风格与后台一致。

## 2. 数据从哪来（构建期生成）

文档数据由 `scripts/gen-api-docs.mjs` 在**构建期**用 TypeScript AST 扫描全部
`src/**/*.controller.ts`（外加 `app.module.ts` 的健康检查）生成，产物为
`src/modules/docs/api-docs.generated.ts`（**自动生成，勿手改**）。

每个接口提取四类信息：

| 字段            | 来源                                              |
| --------------- | ------------------------------------------------- |
| `method`/`path` | `@Controller('x')` + `@Get('y')` 等 HTTP 装饰器   |
| `summary`       | 方法上方的 **JSDoc**（多行折叠为一段）            |
| `permission`    | `@RequirePermissions(...)` 的全部权限码           |
| `isPublic`      | 是否带 `@Public()`                                |
| `action`        | `@OperationLog('模块', '动作')` 的「模块 · 动作」 |

模块展示名（分组）优先取该控制器内 `@OperationLog` 出现最多的 module 名；纯读控制器
（仪表盘 / 健康检查）用脚本里的 `GROUP_OVERRIDES` 显式指定。

**为什么构建期生成而非运行时反射**：① 说明文案的唯一事实来源是代码里的 JSDoc，
运行时 JS 已丢失注释、读不到；② 运行时零反射开销，产物即数据；③ 与既有的
`prisma:comments` 生成式脚本同风格。

## 3. 用法与维护

```bash
cd ly-admin-api
npm run docs:gen     # 手动重新生成（一般无需手动执行）
npm run build        # prebuild 会自动跑 docs:gen
```

- **新增 / 修改接口后**：正常写控制器即可（写好 JSDoc、`@RequirePermissions`、`@OperationLog`），
  重新生成后文档自动同步——**无需手工维护文档**。
- `npm run start:dev`（`nest start --watch`）不会触发 `prebuild`，若在开发中想立即看到新接口，
  手动执行一次 `npm run docs:gen` 即可。
- 生成物已入库；`GET /api/docs` 直接读取该常量，不在请求期做任何扫描。

## 4. 约定与注意

- 响应同样走统一信封：`GET /api/docs` 返回 `{ code, message, data }`，`data` 为
  `{ groups, total, generatedAt }`（`generatedAt` 在请求时填充）。
- 该接口是 `@Public()`：**无需登录**即可访问（供前端文档页与外部消费）；因此不要把
  它当作需要鉴权的资源。若要收紧，去掉 `@Public()` 并补权限码即可（前端页面本身在后台内）。
- 契约测试 `test/contract.e2e-spec.ts` 的「接口文档」用例锁定了信封、下界规模
  （`total >= 60`）与若干取样接口的形状；新增接口只需保证文档可生成即可。
- 前端页面为纯只读展示，不涉及任何写操作；菜单节点 key 为 `docs`，已授权给
  `super_admin` / `admin` / `viewer`。
