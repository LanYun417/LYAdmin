## 2. 分层职责

| 层         | 只做                                                            | 不做                                            |
| ---------- | --------------------------------------------------------------- | ----------------------------------------------- |
| controller | 解析入参、调用 service、返回数据或 `ResponseEnvelope`、挂装饰器 | 不写业务规则、不直接访问 Prisma、不手写响应     |
| service    | 业务规则、事务、数据访问、缓存失效                              | 不读写 `Request` / `Response`、不依赖 HTTP 语义 |
| dto        | 入参结构与校验规则                                              | 不放业务逻辑、不查库                            |
| common     | 跨模块基础设施与纯函数                                          | 不放某个业务域专属逻辑                          |
| prisma 层  | 连接生命周期、种子                                              | 不写业务查询                                    |

**唯一操作层**：每张核心表只允许一个 service 直接读写。例如 `User / UserRole` 只由 `users.service` 操作，
`Menu` 只由 `menu.service` 操作。跨模块需要数据时注入对方 service，而不是各自写一份 `prisma.user.*`。

## 3. 命名约定

- 文件名 `kebab-case` + 语义后缀：`*.module.ts` / `*.controller.ts` / `*.service.ts` / `*.dto.ts`。
- 类名 `PascalCase`：`UsersModule`、`UsersController`、`UsersService`、`CreateUserDto`。
- 模块目录用领域名：`auth` / `users` / `roles` / `depts` / `menu` / `dict` / `config` / `logs` / `files` /
  `dashboard` / `profile` / `gen`。**新增模块一律用单数领域名**（如 `notice/`）；既有复数目录不做无收益重命名。
- 路由前缀由对外契约决定（`@Controller('users')`），**不要求**与目录同名；改前缀属于破坏性变更。
- 常量集中到 `common/constants.ts`，不在业务代码里写魔法字符串（权限码、状态值、错误码）。
- 环境变量只允许出现在 `common/config.ts`。

## 4. 新增一个业务模块

1. **数据模型**：在 `prisma/schema/` 对应域文件里加 model（新域则新建 `<域>.prisma`），
   字段写 `///` 说明，执行 `prisma:push` + `prisma:comments` + `prisma:generate`。
2. **目录**：`src/modules/<domain>/` 下建 `xxx.module.ts` / `xxx.controller.ts` / `xxx.service.ts` / `dto/xxx.dto.ts`。
3. **DTO**：所有字段必须有校验装饰器（见 08），路径 `:id` 用 `IdParamDto`。
4. **权限**：为接口分配权限码并加 `@RequirePermissions`；只读接口用 `:list` / `:query`，写接口用 `:add` / `:edit` / `:remove`。
5. **留痕**：写操作加 `@OperationLog('模块名', '动作')`。
6. **注册**：把模块加进 `app.module.ts` 的 `imports`（`CommonModule` / `PrismaModule` 已全局，无需重复导入）。
7. **菜单与种子**：在 `seed.service.ts` 的菜单种子里补目录 / 菜单 / 按钮节点与权限码，保证新库开箱可用。
8. **测试**：纯逻辑补单测；对外接口补契约断言（结构 + 关键值）。
9. **文档**：若引入新的横切约定，同步本目录对应章节。

> 第 1、6、7 步与代码生成器（`/api/gen`）的产物一致；用生成器落地后仍需按上面清单逐项复核。
