# 01 - 快速开始

## 1. 环境要求

| 项      | 要求                                                          |
| ------- | ------------------------------------------------------------- |
| Node.js | `>= 24.0.0`（`ly-admin-api/package.json` 的 engines 声明）    |
| npm     | `>= 10`，不要用 pnpm / yarn（根锁文件是 `package-lock.json`） |
| MySQL   | 8.x，库名 `ly_admin`，字符集 utf8mb4                          |
| Redis   | 可选。验证码共享、登出黑名单、登录限流依赖它；不配则降级      |

## 2. 建库

```sql
CREATE DATABASE IF NOT EXISTS `ly_admin`
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_general_ci;
```

## 3. 安装依赖

```bash
# 根目录：工程规范工具 + husky 钩子（务必先装，否则提交钩子不生效）
npm install

cd ly-admin-api && npm install
```

## 4. 配置环境变量

```bash
cd ly-admin-api
cp .env.example .env
```

至少改这几项：

| 变量                 | 说明                                                              |
| -------------------- | ----------------------------------------------------------------- |
| `DB_HOST` 等 `DB_*`  | 数据库连接信息（也可用 `DATABASE_URL` 覆盖）                      |
| `JWT_ACCESS_SECRET`  | 必填，32 字节随机 hex                                             |
| `JWT_REFRESH_SECRET` | 必填，32 字节随机 hex，且**必须与 access 不同**，否则服务拒绝启动 |

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

生成两次，分别填入两个变量。完整变量清单见 `README.md` 的「环境变量」一节与 `.env.example` 注释。

## 5. 建表、注释与种子

```bash
cd ly-admin-api
npm run prisma:push        # 按 prisma/schema/ 建表 / 同步结构（首次必执行）
npm run prisma:comments    # 把 schema 的 /// 同步成库内表/字段 COMMENT（幂等）
npm run seed               # 写入默认菜单/角色/用户/字典/参数（幂等；启动时也会自动执行）
```

> Prisma 7 不提供运行时 DDL，服务启动时**不会**建表。`prisma:push` 会重建表并清空 COMMENT，
> 因此推送后务必再跑一次 `prisma:comments`。

## 6. 启动

```bash
npm run start:dev          # watch 模式，默认 http://localhost:3000
# 或
npm run build && npm run start:prod
```

验证：

```bash
curl http://localhost:3000/api
# {"code":200,"message":"success","data":{"name":"ly-admin-api","status":"ok",...}}
```

默认账号 `admin / 123456`（首次启动由种子写入，部署后请立即修改）。

## 7. 常用脚本

| 命令                            | 说明                                    |
| ------------------------------- | --------------------------------------- |
| `npm run start:dev`             | Nest watch 模式                         |
| `npm run build`                 | 编译到 `dist/`                          |
| `npm run start:prod`            | 运行 `dist/main`                        |
| `npm run typecheck`             | 全量类型检查（`--incremental false`）   |
| `npm run lint`                  | oxlint（type-aware）                    |
| `npm run test`                  | vitest 单测                             |
| `npm run test:e2e`              | e2e（契约 + 冒烟），需 MySQL / Redis    |
| `npm run prisma:push`           | 同步表结构                              |
| `npm run prisma:comments`       | 同步表 / 字段 COMMENT                   |
| `npm run prisma:comments:check` | 检查 COMMENT 是否漂移（有差异退出码 1） |
| `npm run prisma:generate`       | 重新生成 Prisma Client                  |
| `npm run prisma:studio`         | 打开 Prisma Studio                      |
| `npm run seed`                  | 单独执行种子                            |

## 8. 跑测试的前置条件

- **单测**（`npm run test`）：纯函数级，无需数据库。
- **e2e**（`npm run test:e2e`）：会真实启动 `AppModule`（含启动种子），并直连 MySQL；
  契约用例还会走真实登录，从 Redis 读取验证码答案。因此需要：
  1. MySQL 已建库并执行过 `prisma:push`；
  2. Redis 可用（`REDIS_HOST` 已配置）；
  3. `CAPTCHA_ENABLED` 保持默认 `true` 也能跑（用例会自行取答案）。

`vitest.config.e2e.ts` 已设置 `fileParallelism: false`：两个 spec 会各自启动一次应用并写种子，
并行会互相干扰统计口径。

## 9. 运行时产物目录

| 目录                    | 内容                              | 是否入库 |
| ----------------------- | --------------------------------- | -------- |
| `ly-admin-api/uploads/` | 上传文件                          | 否       |
| `ly-admin-api/cache/`   | 图片缩放缓存                      | 否       |
| `ly-admin-api/logs/`    | 按天切分的日志与归档              | 否       |
| `ly-admin-api/web/`     | 前端构建产物（同源部署时托管）    | 否       |
| `ly-admin-api/dist/`    | 编译产物                          | 否       |
| `src/generated/prisma/` | Prisma Client（提交入库，勿手改） | 是       |
