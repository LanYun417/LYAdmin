# 03 - 环境与配置

## 1. 唯一入口

`src/common/config.ts` 是**全项目唯一**读取 `process.env` 的地方：

- 业务代码一律 `import { config } from '../../common/config.js'`，不要在模块里直接读环境变量。
- 启动时先加载 `ly-admin-api/.env`，**已存在的环境变量优先**（便于容器 / 命令行覆盖）。
- `.env` 采用 `KEY=VALUE`，支持成对引号；不引入 dotenv，保持零运行时依赖。

```ts
// ✅
const limit = config.upload.maxSize;
// ❌
const limit = Number(process.env.UPLOAD_MAX_SIZE);
```

## 2. fail-fast 规则

配置错误一律在**启动时**暴露，不允许带病运行：

| 场景                                                  | 行为                                                 |
| ----------------------------------------------------- | ---------------------------------------------------- |
| `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` 缺失或为空 | 抛错，服务拒绝启动                                   |
| 两个 JWT 密钥相同                                     | 抛错，服务拒绝启动（防止 Token 混用）                |
| 日志保留天数 ≤ 0 / 非整数 / 非数字                    | 回退默认值并打印告警（`retention = 0` 会删光日志表） |
| Redis 未配置                                          | 视为「不启用」，相关增强降级，不阻塞主流程           |
| 上传目录 / 日志目录不存在                             | 启动时自动创建                                       |

## 3. 配置分组

| 分组           | 关键项                                                                                | 说明                                                   |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `env` / `port` | `NODE_ENV` / `PORT`                                                                   | 端口默认 3000                                          |
| `trustProxy`   | `TRUST_PROXY`                                                                         | 默认 0，不信任 `X-Forwarded-For`（防伪造 IP）          |
| `db`           | `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` / `DB_CONNECTION_LIMIT` | 连接池上限默认 10（1~100）；`DATABASE_URL` 仅 CLI 使用 |
| `jwt`          | 两个密钥 + 有效期（默认 access 2h / refresh 7d）                                      | 密钥无默认值                                           |
| `captcha`      | `CAPTCHA_ENABLED` / `CAPTCHA_TTL_MS` / `CAPTCHA_LENGTH`                               | 默认开启，5 分钟、4 位                                 |
| `upload`       | 目录、路由前缀、缓存目录、大小 / 数量上限、Referer 白名单                             | 缓存目录必须在静态根之外                               |
| `web`          | `WEB_DIST_DIR`                                                                        | 同源部署时托管前端产物                                 |
| `redis`        | `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` / `REDIS_DB`                           | `REDIS_HOST` 为空即不启用                              |
| `corsOrigin`   | `CORS_ORIGIN`                                                                         | 逗号分隔多个来源                                       |
| `log`          | 目录、归档时刻、慢 SQL 阈值、三类日志保留天数                                         | 归档 00:05、清理 00:10，刻意错开                       |

类型转换统一走 `toNumber` / `toBoolean` / `parseRetentionDays`：空串与非法值回退默认值，
**绝不**把 `''` 静默当成 `0`。

## 4. 应用装配

`src/app.setup.ts` 的 `configureApp()` 被 `main.ts` 与 e2e 共用，保证「跑的装配」与「测的装配」一致：

| 配置           | 值 / 行为                                                         |
| -------------- | ----------------------------------------------------------------- |
| 全局前缀       | `api`（前端 baseURL `/api`）                                      |
| 适配器         | `OkExpressAdapter`：成功响应恒 HTTP 200                           |
| 请求体上限     | JSON / urlencoded 均 2MB                                          |
| 校验管道       | `whitelist: true`、`transform: true`、`enableImplicitConversion`  |
| CORS           | `CORS_ORIGIN` 为 `*` 时反射来源，否则按逗号白名单                 |
| `x-powered-by` | 关闭                                                              |
| `etag`         | 关闭（避免动态响应产生 304）                                      |
| 响应压缩       | >1KB 的 JSON / JS / CSS / SVG 按 `Accept-Encoding` 输出 br / gzip |
| 静态缓存       | 构建产物 `1y + immutable`、上传文件 `30d + immutable`             |
| 预压缩静态     | 优先发送构建期 `.br` / `.gz`，未命中再回落原文件                  |
| 静态资源       | `serveStatic: true` 时才挂载 uploads 与前端产物                   |
| history 回退   | 仅接管 `Accept: text/html` 的 GET/HEAD，其余交还路由              |

> 新增全局配置（管道、拦截器、前缀、CORS 等）必须写进 `configureApp`，不要在 `main.ts` 里单独加，
> 否则 e2e 实例与生产实例会分叉。

## 5. 部署相关

- 反向代理后部署时设置 `TRUST_PROXY=1`，否则限流与审计日志拿到的是代理 IP。
- 生产环境用 `NODE_ENV=production`，`UPLOAD_DIR` / `LOG_DIR` / `cache` 必须可写且持久化。
- 同源部署把前端产物构建到 `ly-admin-api/web/`（或 `WEB_DIST_DIR` 指向的目录），后端会自动托管并做 history 回退。
- `CORS_ORIGIN` 与 `UPLOAD_ALLOWED_REFERERS` 在分离部署时必须显式配置，否则分别出现跨域失败与静态资源 403。
