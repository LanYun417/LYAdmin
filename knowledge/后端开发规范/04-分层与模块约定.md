# 04 - 分层与模块约定

## 1. 模块骨架

一个业务模块固定四个文件（`dto/` 按需增减）：

```ts
// notice.module.ts
import { Module } from '@nestjs/common';
import { NoticeController } from './notice.controller.js';
import { NoticeService } from './notice.service.js';

@Module({
  controllers: [NoticeController],
  providers: [NoticeService],
})
export class NoticeModule {}
```

- `PrismaModule` 与 `CommonModule` 都是 `@Global()`，**不要**在业务模块里重复 import。
- 模块内新增的 provider 必须在本模块 `providers` 注册；跨模块复用请放进 `CommonModule` 并导出。
- 模块必须在 `app.module.ts` 的 `imports` 中注册，否则路由不会生效。

## 2. Controller 约定

```ts
@Controller('notices')
export class NoticeController {
  constructor(private readonly noticeService: NoticeService) {}

  /** 分页列表。 */
  @Get()
  @RequirePermissions('system:notice:list')
  list(@Query() query: Record<string, unknown>): Promise<unknown> {
    return this.noticeService.listNotices(query);
  }

  /** 新增（写操作必须留痕）。 */
  @Post()
  @RequirePermissions('system:notice:add')
  @OperationLog('通知管理', '新增')
  async create(@Body() dto: CreateNoticeDto): Promise<ResponseEnvelope<unknown>> {
    const data = await this.noticeService.createNotice(dto);
    return { __raw: true, data, message: '新增成功' };
  }

  /** 详情：路径 id 统一用 IdParamDto。 */
  @Get(':id')
  @RequirePermissions('system:notice:query')
  detail(@Param() params: IdParamDto): Promise<unknown> {
    return this.noticeService.getNoticeDetail(params.id);
  }
}
```

规则：

- **装饰器顺序**：HTTP 方法 → 权限码 → 操作日志。顺序不影响运行，但统一后便于扫描。
- **返回值**：默认直接返回业务数据，由 `ResponseInterceptor` 包装；需要自定义提示语时返回
  `{ __raw: true, data, message }`（类型 `ResponseEnvelope<T>`）。
- **路径参数**：必须用 `@Param() params: IdParamDto`，不要 `@Param('id') id: string` 再 `Number(id)`
  —— 非法 id 会在 `BigInt(NaN)` 处抛 500，而 DTO 会稳定返回 400。
- **禁止**：controller 注入 `PrismaService`、手写 `res.json()`、拼接 SQL、做业务判重。
- **文件下载 / CSV 导出**：用 `@Res()` 并加 `@RawResponse()`，跳过统一包装。

## 3. Service 约定

```ts
@Injectable()
export class NoticeService {
  constructor(private readonly prisma: PrismaService) {}

  async getNoticeDetail(id: number): Promise<NoticeItem> {
    const row = await this.prisma.notice.findUnique({ where: { id: BigInt(id) } });
    if (!row) {
      throw AppException.notFound('通知不存在');
    }
    return this.toItem(row);
  }
}
```

- 只依赖 `PrismaService` 与其它 service；不出现 `Request` / `Response` / 状态码。
- 业务失败一律 `throw AppException.badRequest / unauthorized / forbidden / notFound / conflict`。
- **BigInt 边界**：数据库 id 是 `BigInt`，对外统一 `Number()`；入参统一 `BigInt(id)`。
- **多表写入**用 `this.prisma.$transaction`，避免半成功。
- **权限相关数据变更**必须清鉴权缓存（见 05 的失效点清单）。
- 列表查询统一用 `parsePagination` / `buildPageResult`，分页响应键固定 `{ list, total, page, pageSize }`。
- 需要部门名时用 `lookupDeptName` / `lookupDeptNames`（批量），不要声明 `User → Dept` 关系（见 07）。

## 4. 跨模块调用

- 需要其它模块的数据能力时，注入对方 **service**，不要复制查询。
- 不要形成循环依赖；出现环时把共享逻辑下沉到 `common/` 或抽独立 service。
- `common/` 只放与具体业务无关的能力；一旦某段逻辑只服务一个域，就应回到该模块。

## 5. 中间件与守卫的边界

| 需求              | 用在哪                                                      |
| ----------------- | ----------------------------------------------------------- |
| 登录校验 / 权限码 | 全局 `AuthGuard` / `PermissionGuard`（APP_GUARD）           |
| 静态资源防护      | 防盗链 + 图片缩放中间件（`/static/*` 不经控制器，免登录）   |
| 请求体 / 响应改写 | 拦截器（`ResponseInterceptor` / `OperationLogInterceptor`） |
| 访问日志          | 中间件 `HttpAccessLoggerMiddleware`                         |
| 统一异常          | 全局过滤器 `AllExceptionsFilter`                            |

守卫只处理「控制器路由」；静态资源、SSE 等不经过控制器的路径要用中间件。

## 6. 菜单层级约定（写错会让页面 404）

`sys_menu.menu_type` 三态：`M` 目录（容器）、`C` 菜单（可路由的**叶子**页面）、`F` 按钮（只提供权限码）。
前端 `buildRoutes` 的规则决定了层级不能用错：

- **只有 `M` 能挂 `C`**；`C` 下面只能挂 `F`（按钮不下发到路由接口，所以路由树里 `C` 必须是叶子）；
- 若把 `C` 挂到 `C` 下，前端会把父节点**降级成 `<router-view>` 透传容器**（丢掉自己的组件，
  并 redirect 到第一个可路由子节点），于是父页面被吞、子页面路径按相对父级 fullPath 计算而错位，
  结果就是 **404**。这个坑真实发生过：把「系统监控」误插进「在线用户」的 children
  （那段 children 本是放「强制下线」按钮的）。
- 自查：`GET /auth/menus` 里 `C` 节点必须没有 `children`；契约 e2e 有专门断言
  （「菜单树结构约束：菜单（C）节点必须是叶子」），动过菜单种子后跑一次 e2e 即可。

⚠️ **改菜单层级后必须手工清掉旧行**：菜单种子按 `(menuName, parentId, menuType)` 匹配已存在记录，
**只创建、不更新、不搬移**（刻意如此：避免每次启动覆盖管理员在界面上改过的名称/图标/排序）。
所以把菜单换到另一个父级下，重新种子会**新建一条**、旧的那条仍挂在原父级，菜单会出现两份。
换层级时先删旧行（含 `sys_role_menu` 授权）再跑种子。
