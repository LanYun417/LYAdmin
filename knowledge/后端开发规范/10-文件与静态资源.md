# 10 - 文件与静态资源

## 1. 上传链路

```txt
multipart 请求
  → multer diskStorage（落盘到 UPLOAD_DIR/<扩展名>，随机文件名）
  → fileFilter：扩展名白名单 + MIME 白名单
  → FilesService：读文件头做幻数校验
  → SHA-256 去重（同哈希复用已有记录，秒传）
  → 写 sys_file 元信息
```

- 白名单在 `common/config/constants.ts`：图片（jpg/jpeg/png/gif/webp/bmp）、文档（pdf/doc/docx/xls/xlsx/txt）、压缩包（zip）。
- 上限：单文件 `UPLOAD_MAX_SIZE`（默认 10MB）、单次 `UPLOAD_MAX_COUNT`（默认 10）。
- 幻数校验防止「改扩展名伪装」；`.txt` 无稳定魔数，只做白名单校验。
- 文件内容落磁盘，数据库只存元信息（原名 / 哈希 / 大小 / MIME / 路径 / 上传人）。
- `POST /api/files/upload` 与头像上传共用 `UPLOAD_MULTER_OPTIONS`，改限制只改一处。

## 2. 存储目录结构

```txt
uploads/
├─ png/   1792321010619_4oz2wenw.png
├─ jpg/   1792321010620_1a2b3c4d.jpg
├─ pdf/   1792321010621_9z8y7x6w.pdf
└─ zip/   1792321010622_5v4u3t2s.zip
```

- **按扩展名分组**：目录名 = 小写扩展名去掉点；异常扩展名归入 `other`（`common/file/storage-layout.ts`）。
  规则收敛在该文件，multer 落盘、入库、缩略图读取三处共用，避免各写一套路径。
- DB 的 `file_name` 存**相对路径**（`png/xxx.png`，posix 分隔符），`file_path` 存 `uploads/png/xxx.png`；
  单条记录自带分组信息，历史平铺数据（`file_name` 无目录）仍由同一套逻辑读取，无需迁移。
- `file_url` 与物理路径同构：`/static/png/xxx.png`，静态托管直接命中。
- 所有读盘入口统一走 `resolveStoredPath()`：越界（`..`、绝对路径）一律返回 null，防目录穿越。

## 3. 秒传

- `GET /api/files/check?hash=<sha256>`：返回 `{ exists, file }`。
- 前端上传前先查哈希，命中则直接复用（`deduplicated: true`）。
- `hash` 必填且必须是 64 位 hex；缺失 / 非法返回 400「hash 非法」。
- **秒传与配额的关系**：配额只统计**真正落盘的字节**，命中秒传的批次不占新空间，因此也不会被配额拒绝。
- **秒传与业务归属的关系**：复用既有记录时**不覆盖**已有归属（同一份内容可能被多个业务引用，先来先得）；
  若既有记录还没有归属而本次上传带了 `bizType`，则补写一次，让「先上传、后关联」的调用也能落到归属。

## 4. 业务归属与上传配额

- **业务归属**：上传时可带 `bizType`（模块标识，如 `avatar` / `notice`，只允许字母数字下划线连字符）
  与 `bizId`（正整数），落库到 `sys_file.biz_type` / `biz_id`，并建 `(biz_type, biz_id)` 联合索引。
  列表支持 `?bizType=x&bizId=y` 反查（`bizId` 仅在带 `bizType` 时生效）。
  典型用途：某个业务单据的附件列表、按模块统计占用。
- **上传配额**：`UPLOAD_USER_QUOTA_MB`（默认 512MB，**0 = 不限**）按 `uploader_id` 聚合已用字节；
  预检放在「秒传筛完之后、落库之前」——命中秒传的文件不占空间，不该因此被拒。
  超限返回 400，消息形如「上传配额不足：已用 12.3MB，本次需 8.0MB，上限 512.0MB；请先删除…」，
  便于用户自助处理；**预检失败会清掉本批已落盘的物理文件**，避免留下无记录可寻的孤儿文件。
- 前端在文件页头部展示「已用 / 上限」（`GET /api/files/quota`），未配置配额时显示「不限量」。
- 只做**单用户**配额，不做全局配额：全局上限需要 `SUM(size)` 全表聚合，代价与收益不匹配；
  单用户配额已能拦住「一个账号塞满磁盘」这个主要风险。

## 5. 静态资源访问

```txt
GET /static/{*path}
  → HotlinkGuardMiddleware （防盗链，失败 403）
  → ImageScaleMiddleware   （?scale= 缩放）
  → express.static(uploads)
```

- 这条链在 `app.setup.ts` 里**按顺序显式挂到 express**（`app.use('/static', ...)`）。
  不要改回 `consumer.apply(...).forRoutes('static/...')`：Nest 的中间件路由会被全局前缀改写成
  `/api/static/...`，永远匹配不到 `/static/...`；且 `useStaticAssets` 注册更早，会抢在中间件之前直接出图，
  导致防盗链 / 缩放全部失效（2026-10-18 修复的真实缺陷）。
- 静态资源不走控制器，因此用中间件处理防盗链与缩放，而非全局守卫。
- 静态资源免登录，浏览器直接请求即可，无需携带令牌（不再有 `?token=` 拼接）。
- 防盗链放行：无 Referer、同源、命中 `UPLOAD_ALLOWED_REFERERS`；其余 403。
- 响应缓存：上传文件名由服务端生成且唯一，静态托管时下发 `Cache-Control: max-age=2592000, immutable`（30 天），重复访问不再回源。
- `?scale=<width>`：合法范围 `1..2000`，超出或非数字忽略；结果缓存为 JPEG(q85)，
  缓存目录 `UPLOAD_CACHE_DIR` **必须位于上传根目录之外**，避免缓存被公开访问。
- **缓存布局**：`<缓存目录>/<sha256(相对路径)>/<宽度>.jpg` —— 用「一级子目录 + 宽度」而非平铺的
  `hash(路径+宽度).jpg`，是为了让「原文件被删除」时能按目录整体清理（平铺布局下宽度组合未知）。
- **缓存清理**（`ImageScaleService`）三条路径：
  1. 删除上传文件时联动 `clearFor(相对路径)` 清掉该文件全部宽度的缓存（`UPLOAD_CACHE_SWEEP_ENABLED=false` 也不影响这条）；
  2. 启动时 + 每 `UPLOAD_CACHE_SWEEP_INTERVAL_HOURS`（默认 6h）执行一次 `sweep()`：先按
     `UPLOAD_CACHE_TTL_DAYS`（默认 30 天）删过期条目，再按 `UPLOAD_CACHE_MAX_MB`（默认 512MB）
     淘汰最久未访问的条目，最后清掉空目录；
  3. TTL 与体积上限都为 0 时 `sweep()` 什么都不删（紧急关断口径）。

## 6. 下载与删除

- `GET /api/files/:id/download`：`@Res()` 写出，文件名去掉 CR/LF 与引号，防止响应头注入。
- `DELETE /api/files/:id`：删除记录与磁盘文件；磁盘删除失败不阻断记录删除（幂等）。
- 路径参数统一用 `IdParamDto`。

## 7. 安全清单

- 不接受客户端传入的存储路径；文件名由服务端生成。
- 不把上传目录映射为可执行资源；静态前缀与物理目录分离（`UPLOAD_ROUTE` vs `UPLOAD_DIR`）。
- 同源部署天然满足 Referer 校验；分离部署必须配置 `UPLOAD_ALLOWED_REFERERS`，否则图片 403。
- 头像等公开图片免登录即可访问，由防盗链保护来源；若需更强约束可单独在路由层加控制。
