# 06 - 响应与异常

## 1. 统一响应体

```jsonc
// 成功
{ "code": 200, "message": "success", "data": { /* 业务数据 */ } }

// 失败
{ "code": 400, "message": "账号不能为空", "data": null }
```

- 成功响应**恒为 HTTP 200**，业务结果看响应体 `code`。POST 不会返回 201（由 `OkExpressAdapter` 统一）。
- 失败响应同时设置 HTTP 状态码与响应体 `code`，两者通常一致（400/401/403/404/409/429/500）。

## 2. 成功响应的三种写法

| 场景                  | controller 写法                                                              |
| --------------------- | ---------------------------------------------------------------------------- |
| 普通数据              | 直接 `return data`，拦截器包成 `{ code: 200, message: 'success', data }`     |
| 需要自定义提示语      | `return { __raw: true, data, message: '新增成功' }`（`ResponseEnvelope<T>`） |
| 二进制 / CSV / 文件流 | `@Res()` 自行写出，并加 `@RawResponse()` 跳过包装                            |

```ts
@Post()
@OperationLog('通知管理', '新增')
async create(@Body() dto: CreateNoticeDto): Promise<ResponseEnvelope<unknown>> {
  const data = await this.noticeService.createNotice(dto);
  return { __raw: true, data, message: '新增成功' };
}
```

> **不要**在拦截器或 controller 里手动 `res.status(200).json(...)` 后再返回数据：响应会被写两次，
> 抛 `ERR_HTTP_HEADERS_SENT`。状态码统一由适配器负责，响应体统一由拦截器负责。

## 3. 错误码

| code | 含义         | 典型场景                              |
| ---- | ------------ | ------------------------------------- |
| 400  | 参数校验失败 | DTO 校验不通过、业务参数非法          |
| 401  | 未认证       | 无 Token、Token 过期 / 无效、账号禁用 |
| 403  | 无权限       | 缺权限码、非数据范围、防盗链          |
| 404  | 资源不存在   | 详情 / 编辑 / 删除找不到记录          |
| 409  | 数据冲突     | 唯一键重复、存在子节点不允许删除      |
| 429  | 请求过于频繁 | 登录连续失败被锁定                    |
| 500  | 服务器错误   | 未捕获异常（会记录 error 日志）       |

新增错误码时改 `common/config/constants.ts` 的 `ERROR_CODE` / `ERROR_MESSAGE`，不要在各模块里写数字字面量。

## 4. 抛异常，不返回错误

```ts
// ✅
throw AppException.notFound('用户不存在');
throw AppException.conflict('角色编码已存在');
// ❌ 控制器里 return { code: 403, ... }
```

`AppException` 提供 `badRequest` / `unauthorized` / `forbidden` / `notFound` / `conflict` / `tooManyRequests`
六个工厂方法；特殊场景可 `new AppException(message, code, httpStatus)`。

## 5. 全局异常过滤器

`AllExceptionsFilter`（`@Catch()`）按以下顺序处理：

1. `AppException` → 采用其业务码与文案。
2. Nest 内建 `HttpException`（含 `ValidationPipe` 的 400）→ 从 `message` 提取文案；
   多个校验错误去重后用 `"; "` 拼接；仍是英文默认文案时说明 DTO 缺少中文 `message`。
3. `MulterError` → 转成「文件大小 / 数量 / 字段」中文提示。
4. 未捕获异常 → 记录 `[UnhandledError]` 日志（含堆栈），响应 500；**不把内部堆栈返回给客户端**。

## 6. 中文文案

- 字段级提示写在各 DTO 内联（如 `{ message: '账号不能为空' }`）。
- 类型 / 长度 / 范围等通用约束用 `common/utils/validation-messages.ts` 的 `MSG`：

```ts
@IsInt({ message: MSG.isInt })
@MaxLength(20, { message: MSG.maxLength(20) })
```

- 禁止漏出 class-validator 英文默认文案（`must be`、`should not be`…）。契约测试会断言校验失败文案含中文。

## 7. CSV 导出

- 用 `@RawResponse()` + `@Res()`，`Content-Type: text/csv; charset=utf-8`。
- 文件带 UTF-8 BOM（防 Excel 中文乱码），行尾 CRLF。
- 时间列按 `x-timezone-offset` 换算后再格式化（`TimezoneOffset` 参数装饰器）。
- 表头与列顺序属于对外契约，改动需同步契约测试。
